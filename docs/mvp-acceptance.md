# Local MVP acceptance

This milestone closes the local task-chat loop: explicit startup configuration → create Bot → submit task → independent Worker → progress/Steer/queued follow-up/Cancel → durable result. The live acceptance below uses FakeAdapter. It proves product flow and SQLite/process integration, not AI reasoning, tools or Linux container isolation. Real Pi remains gated by the Linux/rootless Docker and model acceptance in [deployment-runbook](deployment-runbook.md).

## First use and recovery

Run `npm ci --ignore-scripts` on Node 24+, then `npm run demo:ui`. Open the printed loopback URL. The launcher chooses a dedicated `.chestnut-demo`, loads no `.env`, disables automatic memory maintenance and Telegram, blocks external Node requests, and starts separate API and Worker processes. It refuses unrecognized/real-mode data. Optional `--data-dir`, `--port`, and `--delay-ms` configure this explicit demo; delay accepts 100–60000ms, default 10000ms. `--port 0` chooses and prints the actual available port. This entry does not replace real-mode `npm run dev` configuration.

Create a named Bot, submit a task, and watch Queued → Running and its Activity events. Select Steer to send a direction while running; HTTP acceptance and `sent_unconfirmed` do not prove that a model applied it. The simulated adapter records it but does not alter its deterministic answer. New follow-up creates a separate queued child task. Cancel shows Cancelling until Worker cleanup settles, then Cancelled; queued descendant work is cancelled. Completed tasks show their stored result.

Ctrl+C and restart the same command to reopen server history. Same-tab reload retains chat drafts, selected task/type and pending Bot/task/command UUIDs in bounded session storage. The page reads `GET /api/bot-requests/:requestId` and Bot-scoped `GET /api/bots/:botId/requests/:messageId` to reconcile accepted sends against current durable results. Reads cannot enqueue or resend work. A missing receipt retains the original UUID for an explicit unchanged retry; changing the content creates a new request and should follow a history check. Storage denial is shown when a send remains unconfirmed. Closing the tab, a different origin, or browser storage eviction can lose unsent drafts/UUIDs; server history is independent.

Expired Steer text stays a Steer draft and requires an explicit type switch before creating a follow-up. Failed, cancelled and interrupted tasks offer **Use prompt for a new task**: this only copies the prompt, refuses to overwrite a different draft or an unconfirmed send, and requires explicit Start. Worker lease expiry preserves interruption/quarantine and does not replay external effects; follow the runbook for uncertain outcomes.

## Automated reproduction

`npm run check` keeps the default external-network guard enabled. `tests/mvp-process.test.ts` runs actual independent CLI API/Worker processes on a temporary loopback port and dedicated disposable SQLite directory. It checks Bot/task deduplication, current receipts, Steer, follow-up completion, cancellation including queued descendants, graceful stop/restart and the same stored identities/results. Listener-denied executors report an explicit skip instead of a simulated live pass. Existing lease/fencing/quarantine tests cover crash recovery.

`tests/api.test.ts` additionally checks Bot request conflicts, invalid/scoped receipt lookups and mutation-free current task/command receipt reads. The 44 mock-DOM dashboard tests cover failed sends and lost accepted acknowledgments across reload, no automatic POST, retained selection/drafts, terminal prompt preparation, no silent Steer conversion, corrupted journals and demo auth exclusion. The actual UI functions also round-trip all 20 task drafts, 30 command drafts and 30 pending UUIDs above the former 2,000,000-character read limit, including JSON-escaped records above 10,000,000 characters. Reads and writes now share a 32,000,000-character serialized safety limit that accommodates the bounded rows; browser quotas may be lower. A quota failure leaves the last saved journal untouched and current drafts/IDs in memory, with a visible copy-before-reload warning even without an unconfirmed send. These controller tests do not constitute browser rendering evidence.
