# Real-host acceptance gate (not run)

Record exact commit, Node version, Linux/kernel/Docker versions, redacted Docker info, immutable image IDs, per-step commands/results and timings. Run on a disposable dedicated rootless account and data volume after explicit operator authorization. Do not install host packages, change security settings, log in, use provider credentials, send Telegram messages or deploy without the corresponding authorization. This file is a checklist, not evidence that the steps passed.

Executable preparation and recovery are in [deployment-runbook.md](deployment-runbook.md). `npm run preflight` is read-only; `npm run acceptance:offline` runs the existing guarded checks. `npm run acceptance:docker` defaults to a plan. Its explicit `--execute --data-dir <new-path>` mode covers the model-less real stable-Docker subset of steps 2–5 with retained evidence. It does **not** certify the Worker/model/package/channel gates below. No Docker execution was performed while preparing these entries on macOS.

1. Run locked installs, `npm run pi:verify`, pinned catalog hydration, actual Pi `build:offline`, `npm run pi:contracts`, `npm run check`, and `npm run demo`. Default tests prohibit external network and remove ambient secret environment variables; Linux must run all Unix listener tests rather than skip them. Inspect the source/run manifest before starting real work.
2. Preflight rootless Docker, util-linux flock and real CPU/memory/PID/swap enforcement. Build the source image. Confirm Debian bookworm, matching architecture, CA roots, archive keyring, apt-get/apt-cache/gpgv/dpkg/env/Node. Use a new service-profile data directory. API stays loopback-only; no host socket or home directory is mounted.
3. Create A and B. With an explicitly authorized test model grant, run A through the actual compiled Pi extension startup, tool call and multi-turn Responses gateway. Confirm readiness rejects a missing/failed environment extension and never runs a builtin shell in the disposable runner. Capture inspected mount/PID/network boundaries for both containers.
4. In A, write `/opt/chestnut-acceptance.txt`, install one small reviewed package through the governed package tool and capture signed-metadata/artifact hashes. First reject an incomplete allowlist, then explicitly approve the complete package/dependency set. No host apt/dpkg. A fresh B must not observe A's workspace, rootfs, processes, package marker, model socket, memory socket or session.
5. Start a tiny HTTP service listening on A's container loopback with an explicit PID file and redirected log. Finish task 1 successfully. In task 2, verify the exact same environment/container identity, marker, package version, PID and local HTTP response. Capture that the old stable process never gains a later model/memory broker mount. A successful test here is the first evidence of actual service continuity.
6. Stop/restart only the Worker while no task is active: rootfs and existing idle service should remain. Separately kill the Worker during a task: lease expiry must interrupt it, cancel dependent follow-ups, clean the disposable runner, stop A, preserve rootfs and avoid prompt/tool replay. Retry only via an explicit new task after review. Verify old delayed lifecycle commands cannot affect a newer owner.
7. Cancel an active task and time out a command. Confirm whole-environment stop and exact task outcome; already-performed changes are not rolled back. Exercise failed runner cleanup, model/memory/environment socket cleanup, wrong/missing container identity, cgroup launch-controller loss and retagged image. Cleanup must stay fail closed; do not remove a lock file to force takeover.
8. Interrupt package operations before download, before import, during dpkg and between install completion/receipt publication. Inspect ownership-matched downloader cleanup and durable pending/contained markers. New work must remain blocked until reviewed; reconcile with exact Bot/Run/container IDs. Verify corrupt signature/hash, symlink artifact, dependency-policy expansion and oversized archive fixtures never import.
9. Test governed HTTPS fetch against an approved public test host and forbidden host, redirect, private/metadata addresses, mixed public/private DNS and stalled DNS/response fixtures. Validate actual DNS pinning and TLS certificate checks. Bot shell and background services must still lack general network; downloader bridge remains a separate fixed trusted operation.
10. Change/log out/reselect the ChatGPT identity/model mid-task. No later request from old context may use the new grant. Same-generation token refresh remains valid. Capture a real tool-result → next-model-request roundtrip including assistant phase and reasoning replay.
11. Exercise memory creation collision, user correction, project unbinding while running, old write receipt replay, forget and long steer maintenance cursor progression. Confirm current-policy authorization and actual model-call accounting.
12. Configure Telegram only through a secure outer-process environment. With the exact approved owner/private chat, verify message → Task, status while busy, steer/cancel/follow-up, final result, restart deduplication and delivery ledger. Unknown owners/groups do nothing. Simulate 429, disconnect and ambiguous send; never silently replay uncertain sends. No public API exposure.
13. Create once and IANA cron schedules through Dashboard. Verify queue admission after Worker restart, no duplicate fire, overlap skip/coalescing, pause/resume and the documented DST fold/gap policy. Existing tasks remain distinct from the schedule's next-fire state.
14. Browser acceptance: inspect desktop and narrow viewport, keyboard/focus, long errors/content, repeated submit, changing Bot during pending requests, close/cancel/reopen, policy revision conflict, old stop retry and schedule retry after due time. Automated DOM tests do not replace this visual pass.

Completion requires saved evidence for these live gates. Until then the service profile, package installation, real channel connection and real-model flow remain experimental and not operationally certified.
